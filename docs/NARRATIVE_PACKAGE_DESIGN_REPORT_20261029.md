# AnimatedScroll 叙事包与「检查与导出」页面改版报告

日期：2026 年 10 月 29 日  
范围：叙事包内容契约、入画对话配置、检查与导出页面，以及现有体验的衔接。

## 1. 设计结论

叙事包需要同时回答三个问题：故事讲什么、观众怎样参与、对应素材在哪里。

因此，本次将交付内容组织为「创作内容＋交互配置＋本地素材＋检查状态」。页面采用「内容总览／入画对话／检查与修复」三个页签，右侧集中呈现预览、草稿导出与已确认导出。

本报告的依据是此前页面改版形成的交互约定、项目现有数据结构，以及入画对话的实际运行流程。页面效果仍应通过后续参与者测试验证。

## 2. 修改依据与发现

| 当前情况 | 对交付的影响 | 本次处理 |
| --- | --- | --- |
| 人物页已采用原画立绘，大纲和剧本按场景组织 | 交付页需要保持相同的识别线索 | 总览使用原画、人物小立绘和逐幕卡片；问答采用立绘选人 |
| 旧导出以项目快照和剧本为主 | 难以从文件中重建观众的提问、回答与解锁步骤 | 显式保存引路人、逐幕问答、线索和解锁条件 |
| 原体验会根据场景标题选择演示问答，并在缺少匹配时从剧本回退 | 作者难以看见或修改真正播放的内容 | 增加可编辑的入画配置；已配置项目由体验直接读取该配置 |
| 观众依次听引路词、选择人物、提问、读回答、记录线索、解锁场景 | 问答缺失或关联失效会使体验停住 | 检查每幕至少一条完整问答、有效回答人物、来源版本和场景对应 |
| 旧页面集中展示格式按钮，具体缺少什么不直观 | 用户需要试着导出后才知道问题 | 自动执行结构检查，列出待处理项并跳转到对应页面 |
| 旧正式导出要求存在一致性检查结果 | 容易把模型调用变成流程门槛 | 新叙事包导出将 AI 检查设为可选；已有未处理建议仍须处理 |
| 动画可能属于旧剧本或测试预览 | 可能播放与当前故事不一致的片段 | 只纳入当前场景、当前内容指纹、成功保存且未标记需重做的正式视频 |
| 创作者需要保留过程记录，观众需要独立阅读进度 | 混入体验包会增加冗余与状态耦合 | 版本记录单独导出；阅读进度保留在读者本机 |

具体核查了 `src/DialogueStage.vue` 的交互阶段、`src/dialogueStory.ts` 的章节构建、`backend/domain.py` 的引用与审核规则，以及 `backend/video.py` 的场景指纹和媒体状态。

## 3. 叙事包内容

| 模块 | 包含内容 | 用途与条件 |
| --- | --- | --- |
| 基本信息 | 包格式版本、项目 ID、项目版本、标题、导出时间、草稿／已确认状态 | 确认交付的是哪一版内容 |
| 原画与人物立绘 | 原画文件、归一化人物框、人物与标注 ID、从原画裁切的立绘 PNG | 支撑姓名牌定位、人物选择与对白形象；正式包要求原画可读取 |
| 人物与创作设想 | 姓名、身份、简介、关系、命名来源、用户创作意图与边界 | 保留创作上下文；创作设想不充当史料 |
| 资料与出处 | 来源 ID、版本、标题、出处、原文、项目改编注记；本地原始文档（若有） | 引用可追溯；区分项目文本与外部原始文献 |
| 逐场故事 | 大纲顺序、场景 ID、目标、衔接、出场人物、剧本段落、依据分类和审核状态 | 为阅读、问答和媒体建立稳定对应 |
| 入画对话 | 可选引路人、每幕体验标题、开场词、收束语、问题、回答、回答人物 | 作者可直接修改实际体验内容 |
| 线索与解锁 | 问答 ID、获得的线索、必须读完的问题集合、对应场景、下一幕 | 支撑观众推进、线索手记与回看 |
| 分镜与动画 | 本场分镜；满足条件的本地视频及相对路径；媒体回退类型 | 视频可选；优先视频，缺少时使用有效分镜，再回退原画 |
| 检查与交付确认 | 结构检查结果、待处理项、可选提示、导出时的人工确认与项目版本 | 明确草稿问题与正式包条件 |
| 创作快照 | `project.json` | 保留完整创作数据，便于追溯与后续接入 |

### ZIP 文件结构

```text
manifest.json                 叙事与交互契约，使用包内素材相对路径
project.json                  当前创作快照
story.md                      人物、剧本、问答、线索和资料的可阅读文本
README.md                     使用说明与运行边界
assets/
  painting/                   当前原画
  portraits/                  原画裁切立绘
  documents/                  可读取的本地原始资料
  videos/                     满足版本和场景条件的正式动画
```

立绘文件名采用稳定摘要，原始标注 ID 保留在清单中。素材打包仅读取项目数据目录内的合法文件，不访问外部网页，不下载远端媒体。

### 三种导出形式

| 形式 | 适用场景 | 边界 |
| --- | --- | --- |
| ZIP | 完整交接与留档 | 包含清单、快照、可阅读文本与实际可用的本地素材 |
| JSON | 程序之间传递结构化内容 | 单文件包含元数据和素材路径，素材文件需要另行保留 |
| Markdown | 阅读、讨论与逐幕核稿 | 包含文本，不携带素材文件，也不能直接运行交互 |

ZIP 是内容与素材包，当前不包含独立播放器或导入向导。外部接收端仍需按清单契约实现读取和呈现。

## 4. 页面设计

### 内容总览

原画封面显示当前故事、人数、场数和问答数。七类内容卡片分别呈现原画、人物、故事、依据、交互、媒体和检查状态。下方逐幕卡片展示剧本段数、问答数、呈现方式与出场人物立绘。

这样能在导出前看见交付内容，并沿用此前「先识别人，再读场景」的页面逻辑。

### 入画对话

先选引路人，再逐幕、逐问答编辑。每条问答提供立绘选人、问题、回答和线索；回答性质与原文引用按需展开。每幕底部直接显示解锁路径。

「同步大纲场景」保留已有场景的问答编辑，只补充新增场景并调整顺序。建立旧项目配置时，从现有体验规则与剧本整理草稿，不调用模型。由作者继续核对其适用性。

### 检查与修复

将相同来源、相同人物定位的重复问题合并到对应待处理项。待核对来源可以在本页展开全文，作者阅读后明确确认并保存；确认只更新审核状态，不改变原文版本。其他修复入口会跳回画作、人物、大纲或具体场景；交互配置问题留在本页处理。可选媒体提示与 AI 检查分开展示。

### 右侧交付面板

集中显示就绪状态、故事规模、导出形式、格式说明和导出操作。草稿始终可导出，保留待处理信息。结构检查通过后，作者确认已审查问答、线索和解锁顺序，才能导出已确认包。任一内容变更会清除该次页面确认。

### 可读性

主标题、内容标题、操作和辅助说明采用分层字号；补充说明提高文字对比度。格式细节留在交付面板，过程日志默认收起，原始 JSON 快照仅在版本详情中展开。

## 5. 自动检查与人工判断

自动检查覆盖：

- 原画文件是否存在、对象 ID 是否重复。
- 人物档案、引路人资格、画中人物对应关系与既有确认状态。
- 大纲场数、场景顺序、剧本是否缺失、剧本段落是否已核对。
- 来源是否已核对、引用是否逐字存在、来源版本是否匹配、创作设想是否被误作依据。
- 每幕问答是否完整、问题 ID 是否唯一、回答人物是否有效、问答是否对应现有场景。
- 逐字原文作答是否能匹配引文；解释推测是否关联原文。
- 动画是否对应当前场景和内容；分镜失效时给出回退提示。

人工仍需判断：资料本身是否可靠、引文是否真正支持解释、角色知识是否越界、前后幕是否提前泄露结局、台词是否自然，以及动画的实际画风与内容是否合适。逐字匹配只能证明文本可定位，不能证明史实或推论正确。

AI 一致性检查可选。结构检查通过并不代表作品已经获得历史学意义上的验证；正式导出中的人工确认也不替代外部专家评审。

## 6. 实现与当前项目迁移

- 新增 `src/NarrativePackage.vue`，替换原「检查与导出」页面。
- 新增 `backend/narrative.py`：提供只读检查、JSON／Markdown／ZIP 导出和素材打包。
- 在 `backend/models.py` 明确定义引路人、章节和问答配置。
- `src/dialogueStory.ts` 优先读取作者保存的交互配置；旧项目保留演示回退路径。
- `src/DialogueStage.vue` 的进度签名覆盖章节内容与引路人配置；内容变化后不复用旧问答的解锁状态。
- 对话变更使旧一致性建议失效，保留未修改剧本本身的审核状态。
- 旧 `/export` 接口继续提供既有格式；新页面使用 `narrative/export`，叙事包格式版本为 `2.0`。旧接口保留原审核规则，新页面使用本报告说明的交付规则。

当前折槛图项目已备份并迁移为版本 102，保留 5 幕、6 条问答、3 位可选引路人和 9 位人物。问答中的人物称谓沿用当前项目设定。迁移不自动批准人物、资料或剧本；页面会继续显示真实的待核对状态。

备份位于项目 `data/backups/`，文件名前缀为 `before-narrative-interaction-`。

## 7. 验证

- 完整后端回归：101 项通过、4 项按环境条件跳过（最终版本）。
- 9 项叙事包专项测试覆盖来源确认时保留引用版本、无效图片的草稿回退、正式导出确认、草稿导出、问答缺失、来源失效、章节顺序、立绘缺失、旧版／测试视频过滤、ZIP 文件路径与本地文件边界。
- 前端生产构建通过。
- 对话逻辑检查通过：引路人筛选、逐幕线索门槛、作者配置优先读取，以及无关项目的回退行为。
- 使用浏览器检查内容总览、逐幕问答编辑、原文依据入口及体验预览；界面截图保存在 `examples/narrative-package-*.png`。

当前项目草稿已实际导出至 `output/narrative-package-draft-v102.zip`：约 1.68 MB，14 个文件，含原画、9 幅立绘、5 幕故事、6 条问答与 3 位引路人配置。当前仍有 17 项待处理，草稿状态如实保留。

本次验证没有调用云端模型生成新问答或动画。ZIP 交付能力与已确认导出门槛通过隔离测试验证；当前创作项目仍按真实审核状态提供草稿与待处理项。

## 8. 后续可验证的问题

后续参与者测试建议观察：用户能否区分「剧本内容」与「体验问答」、能否理解草稿与已确认包的差别、能否通过待处理项找到修复入口，以及是否需要批量核对同一幕内容的操作。若需要多分支剧情，应在当前线性逐幕契约之上增加分支与汇合规则，并同步扩展播放器和结构检查。
